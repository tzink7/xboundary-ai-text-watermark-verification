AI-text watermark & DNS verification

Watermark a piece of text, verify it against a key published in DNS, build a _watermark-text record, or lint every record a domain publishes.

Demonstration only. tzsataitw-1 (zero-width characters) and tzsataitw-2 (look-alike letters) are steganographic short-text marks — easily stripped by normalisation. fairoze-1 is the publicly-detectable [Fairoze23] construction (Ed25519 variant) — unforgeable, but needs ~700+ words and breaks on almost any edit; its samples here are pre-generated. All three demonstrate the same asymmetric verify-via-DNS loop. Signing uses dedicated demo keys.

Watermark text

Sign your text with one of this server's demo keys and hide the 64-byte signature inside it. The signature covers "<algorithm>\n" + canonical_text — never the locator.

Each key signs one fixed algorithm — the one its _watermark-text record publishes in a=. It is not selectable here: signing with a different algorithm would just fail verification.

These fairoze-1 watermarks were generated once on an open-weight model — the mark is spread across the whole text as a statistical bias, so there is nothing to “add” here. This server can’t run the generator (it needs a GPU); it just serves the finished text. Take it to the Verify tab with domain demo.terryzink.com.


      

        
        
      

      

    

  


  
  

    
Verify text

    
Detects the channel, recovers the signature, fetches the public key from
      DNS, and checks it. When the key comes from DNS, the record's a= must also
      match the mark's algorithm or the mark is rejected.

    
    
      
  • Leave both blank — use the locator embedded in the watermark.
    • 
      
  • Domain only — crawl 1._watermark-text.<domain>,
        2., … until one selector verifies the signature (up to 10).
    • 
      
  • Domain + selector — check only that one record.
    • 
    

    
fairoze-1 marks carry no embedded locator, so
      “leave both blank” can’t work for them — you have to name the
      domain. That is the point: an independent verifier cannot check a fairoze-1
      mark without being told which provider generated the text.


    
    

    

      

        
        
      

      

        
        
      

    


    
    


    

      

      

      

    

  


  
  

    
Build a DNS record

    
Generates a fresh key pair plus the matching
      <selector>._watermark-text.<domain> TXT record. The private key
      is handed to your browser for download and is not stored here.


    

      

        

      

    

    

      

        
        
      

      

        
        
      

      

        
        
      

    


    
    


    

      
      

      
      

      

        
        
      

      
      

    

  


  
  

    
Validate a domain

    
Crawls 1._watermark-text.<domain> onward (following
      r=), lints every selector against the draft's rules, and fetches each
      d= document over HTTPS to check its hash and schema.
